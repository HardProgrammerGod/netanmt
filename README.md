# Neta NMT English — Telegram Product v3

Це фінальний Telegram-first реліз перед активною розробкою Web-версії. Він зберігає чинні дані, Premium-права та історію платежів, але змінює активний продукт навколо короткого персоналізованого навчання.

## Що відрізняє Neta

Основна продуктова механіка — **Neta Memory**:

1. учень проходить короткі сесії по 3–5 питань;
2. помилки та конкретні навички зберігаються в PostgreSQL;
3. наступні заняття змішують актуальні помилки з новими завданнями;
4. прогрес показує сильніші навички та те, що варто повторити;
5. коротка вправа ніколи не видається за достовірний рівень англійської або прогноз бала НМТ.

Це не просто каталог тестів: цінність накопичується між заняттями.

## Основний шлях нового користувача

`/start` → сильна коротка обіцянка → **«Побачити Neta в дії · 3 питання»** → перший профіль навичок → Neta Memory → **перше повне заняття ~5 хв** → добровільне нагадування → прогрес / канал / друзі / курс.

Три стартові питання беруться з curated intro-набору. Якщо потрібних кодів у конкретній БД немає, PostgreSQL автоматично підбирає approved + active fallback.

## Діагностика

Довга діагностика більше не блокує onboarding. У «Мій прогрес» є добровільна **«Карта навичок · 12 питань»**. Вона використовується для ширшої картини сильних/слабких навичок, але не показує псевдоточний бал НМТ.

## Telegram-канал

Канал продукту: https://t.me/neta_nmt

Він інтегрований після отриманої користі, а не як примусова умова входу:

- окрема кнопка в головному меню;
- CTA після intro;
- CTA після Daily;
- екран пояснює різницю: бот = персональна практика, канал = безкоштовні розбори/контент/оновлення.

Подія `channel_view` вимірює відкриття CTA-екрана. Вона **не означає гарантовану підписку** — це чесна метрика наміру. Для атрибуції людей, які приходять з каналу в бота, використовуйте у постах/описі посилання виду:

`https://t.me/netaNMT_bot?start=channel_neta`

Тоді `acquisition_source = channel_neta`.

## Навчальна модель

- Intro: 3 curated питання.
- Daily: 4 питання за замовчуванням (у межах цілі 3–5).
- Daily спочатку бере до половини актуальних помилок користувача, решту — ще не бачені питання, потім approved fallback.
- Неактивні, diagnostic та не-approved питання не потрапляють у звичайне Daily.
- Стан сесії, позиція та відповіді зберігаються в PostgreSQL.
- Повторний callback не зараховує відповідь двічі.
- Правильність відповіді визначає БД за `questions.correct_option`; клієнтському `is_correct` не довіряємо.
- `user_topic_progress` оновлюється атомарно в тій самій DB-транзакції, що й відповідь.

## Retention

- Після першої сесії можна добровільно вибрати 17:00 / 19:00 / 21:00 за Києвом.
- Нагадування легко вимкнути.
- Після завершеного Daily цього дня воно не надсилається.
- Після `TelegramForbiddenError` користувач позначається неактивним, reminders вимикаються.
- Тексти без сорому, погроз або штучного streak-pressure.

## Друзі

- персональне referral-посилання;
- atomic referral activation;
- добровільний тижневий рейтинг;
- максимум 1 бал за завершений навчальний день;
- публічно показується лише згенерований псевдонім;
- ім’я, username, місто, школа та Telegram ID не публікуються.

## Курс

Активні Premium-продажі прибрані з основного UX. Старі `orders`, `is_premium`, `premium_until` та обробка вже розпочатих Stars-платежів залишені для сумісності.

«Про курс»:

- чесно повідомляє, що структурований курс готується;
- може прив’язати пояснення до слабшої навички користувача;
- має CTA «Мені цікаво»;
- окремо вимірює `course_view` і `course_interest`;
- не використовує фальшиві відгуки, місця чи дефіцит.

## Аналітика

Новий Learning report агрегується всередині PostgreSQL, щоб API row limits не спотворювали цифри при рості бази.

Відстежуються:

- acquisition source;
- value proposition shown;
- first lesson started/completed;
- question shown/answered та dropout;
- Daily started/completed;
- diagnostic started/completed;
- repeat learning days;
- D1/D3/D7 лише для matured cohorts;
- course view / interest;
- channel view;
- referral visit / activation;
- p50/p95 latency;
- errors.

Admin IDs і `is_test_account=true` виключаються з продуктового звіту.

## Архітектура

- Python 3.11+
- aiogram 3.x
- aiohttp webhook
- Supabase PostgreSQL
- Render-compatible `render.yaml`

Критичний навчальний state не залежить від `MemoryStorage`. MemoryStorage використовується тільки для тимчасового FSM адмінки додавання питання; рестарт не стирає учнівську сесію.

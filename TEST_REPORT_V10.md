# Перевірка v10 · 17.09.2026

## Пройшло локально

- 7 поведінкових Python-тестів доставки: успіх; вимкнення/завершення перед надсиланням; блокування; 429; timeout без повтору; збій БД після надсилання без дубля; 30 підказок та обмеження callback_data.
- SQL виконано у локальному PostgreSQL-сумісному PGlite на мінімальній тестовій схемі. Використано фіксований час; production SQL не змінює системний годинник.
- Міграція виконана двічі: збережено явне вимкнення та індивідуальний час; зміна налаштувань після першої міграції не скасована повторною.
- Точний результат 1507 питань; виручка лише за paid/XTR, без pending та іншої валюти.
- Перевірені нові, неактивні, тестові користувачі, відмова, завершене заняття, інший час, інтервали 3/7 днів, пауза після 7 ігнорувань, 30-денна неактивність, повторне резервування того самого дня.
- Повторне ввімкнення поновлює цикл; завершення після резервування й нічний час блокують надсилання.
- Воронка враховує перше записане джерело за всю історію; повторний /start старого користувача не збільшує залучення; поточний день не є завершеним спостереженням retention.
- Попередній tools/smoke_test_learning_v7.py пройшов: це статичні перевірки попередніх інваріантів, не повний end-to-end тест.
- tools/security_check.py: очевидних зашитих токенів/ключів не знайдено. Це не повний аудит безпеки.
- Python compileall і реальний імпорт handlers/admin з фіктивними налаштуваннями пройшли. Вихідних запитів до Telegram/робочої Supabase під час цього тесту не робили.

## Межі перевірки

Робочої схеми та облікових даних Supabase/Telegram/Render не було. Тестова схема перевіряє нову SQL-логіку, але не відтворює всі старі тригери, RLS і дані production. Після deploy потрібен контрольний прохід зі START_HERE_V10.md. Фактична кількість питань, доставлюваність на твоєму хостингу та приріст утримання поки не підтверджені.

Платний курс не створено. Новий checkout не додано. Старі обробники платежів збережено, їхню поведінку із справжніми платежами цим релізом не сертифіковано.

# Neta v11 — встановити одразу замість v10

Цей комплект включає всі зміни v10, виправлення рівнів і запрошення до рейтингу. Попередньо встановлювати v10 не потрібно.

## Встановлення

1. Збережи поточний код/commit та резервну копію БД.
2. Зупини старий процес бота на час оновлення, щоб старий планувальник нагадувань не працював одночасно з новим.
3. Supabase → SQL Editor: запусти **тільки migrations/2026_09_17_product_v11_ALL.sql**, повністю. Не запускай окремо v10, v4 чи v7. Прикріплений тобою CREATE TABLE export теж не запускай — це опис існуючої бази.
4. Заміни файли коду в GitHub вмістом цього комплекту та зроби deploy Render. Не додавай вкладену папку поверх старої: main.py та requirements.txt мають лишитися в корені проєкту.
5. Змінні оточення залишаються попередніми. На сервері потрібен SUPABASE_SERVICE_ROLE_KEY. RETENTION_ENABLED=true (типово) дозволяє нагадування; false зупиняє новий планувальник без зміни налаштувань людей.
6. Контрольний прохід: /start → Daily → результат → вступ у рейтинг → наступне тренування → результат без повторного запрошення → Меню. У «Мій прогрес» є ігровий рівень, XP і залишок до наступного.

SQL — одна транзакція. Вона відновлює узгоджені з наданим кодом RPC-функції, потрібні унікальні індекси, додає v10 та тригер рівня. Повторний запуск не нараховує XP повторно й не вмикає назад збережені відмови від нагадувань. Користувачі, питання, відповіді й платежі не видаляються. Існуючі XP не нормалізуються й не обнуляються.

В експорті CREATE TABLE немає визначень функцій, тригерів, RLS та більшості індексів. Саме тому в комплекті відновлюються функції, а сумісність перевірена на структурі таблиць окремим інтеграційним тестом. Неочікувані сторонні тригери чи дублікати, що порушують унікальність, неможливо виключити за одним експортом схеми. У разі SQL-помилки транзакцію не слід продовжувати частинами й не потрібно видаляти дані.

## Рівні

Формула: level = 1 + floor(max(xp, 0) / 100).

| XP | Ігровий рівень |
|---|---|
| 0–99 | 1 |
| 100–199 | 2 |
| 200–299 | 3 |
| 300–399 | 4 |

За 245 XP буде рівень 3, до наступного — 55 XP. Старі користувачі отримають правильний рівень після міграції. Далі він перераховується в тій самій операції БД, що змінює XP. Це ігровий прогрес, не рівень англійської A1–C2 і не прогноз бала НМТ. XP, уже зароблений цього тижня, враховується рейтингом після добровільного вступу за старими правилами.

## Кнопки після Daily і додаткової практики

- 5 питань: закріпити помилки або спробувати складніше.
- Повне тренування на 10 питань.
- «Долучитися до рейтингу» лише при leaderboard_opt_in=false.
- «Меню» повертає до чинного головного екрана з прогресом та іншими розділами.

Вступ залишається добровільним. Після вступу повторна пропозиція на нових результатах зникає. Якщо налаштування тимчасово не прочитались, результат заняття відкривається, а запрошення не вгадується.

## Нагадування v10 збережені

30 підказок, типово 19:00 за Києвом, інтервали 1 → 3 → 7 днів і пауза, вимкнення одним натисканням, пропуск після вже завершеного заняття, захист від повторної доставки. Після 7 успішних повідомлень без заняття або 30 днів без занять — пауза; явний вибір часу чи завершене заняття поновлює цикл. Давній «Не зараз» у старому коді не мав події; відновити такий вибір з відсутніх даних неможливо.

Процес бота має працювати у вікно доставки. Якщо він зупинений або приспаний на весь цей час, нагадування буде пропущене. При невизначеному результаті Telegram-повідомлення того дня не повторюється.

Відкат на старий код: спершу зупинити процес і вимкнути нагадування в БД, попередньо зберігши налаштування. Старий код не читає RETENTION_ENABLED і не знає нових правил.

## Перевірка після deploy

У SQL Editor ці запити лише читають дані:

```sql
select count(*) as all_questions from public.questions;
select count(*) as level_mismatches from public.users
where level is distinct from 1 + greatest(coalesce(xp,0),0)/100;
```

Очікування: all_questions збігається з адмінкою; level_mismatches = 0. Нуль помилок тут не замінює один контрольний прохід Telegram.

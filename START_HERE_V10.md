# Neta · продуктовий реліз v10

Повний код бота, 30 корисних підказок, адаптивні автоматичні нагадування, точна статистика та план розвитку. Підготовлено 17.09.2026 за наданим ZIP і статистикою. Реальний Telegram / Supabase / Render не змінено.

## Що запускати

Якщо твій чинний бот відповідає прикріпленому коду v7:

1. Збережи поточний commit і резервну копію БД штатним способом.
2. Зупини старий процес бота на час оновлення: старий планувальник не знає про нові правила. Не тримай одночасно старий і новий процес.
3. У Supabase → SQL Editor виконай **migrations/2026_09_17_product_v10.sql** цілком. Міграція транзакційна, повторний запуск допустимий. Вона не видаляє користувачів, питання, відповіді чи платежі.
4. Заміни код у своєму GitHub файлами цього архіву й зроби deploy на Render. Змінні BOT_TOKEN, SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY, ADMIN_IDS, WEBHOOK_BASE_URL залишаються твоїми.
5. Перевір /start, одне заняття, налаштування, «Статистика» та «Growth funnel» в адмінці. Для порівняння кількості питань: `select count(*) from public.questions;`.
6. Перевір нагадування на своєму окремому тестовому користувачі з дозволеними підказками; у кандидати автоматично не входять користувачі з is_test_account=true. Для контрольного тесту використовуй лише власний акаунт без цього прапорця, з віком запису понад 20 годин та без завершеного заняття сьогодні. Час змінюється в налаштуваннях.

Якщо в базі немає learning_sessions або функцій v7, спершу застосуй інструкції INSTALL_V4.md / INSTALL_V7.md відповідно до фактичної версії. v10 — оновлення існуючого бота, не повна інсталяція порожньої бази. Не запускай навмання старі контентні SQL.

## Як працюють нагадування

- Для нових користувачів — увімкнено, типово 19:00 Europe/Kyiv; літній/зимовий час враховує часова зона.
- Для існуючих активних — автоматичне ввімкнення, якщо немає збереженої явної відмови. Збережений час не змінюється.
- Історичні події reminder_disabled/reminder_skipped зберігають відмову. Старий callback «Не зараз» не записував подію, тому такі давні натискання неможливо достовірно відновити. Новий callback записує вимкнення.
- Перше повідомлення — не раніше ніж через 20 годин після створення користувача. Завершив будь-яке заняття сьогодні — підказки цього дня немає.
- Перші 3 успішні повідомлення без завершеного заняття — максимум раз на день; потім мінімум 3 календарні дні між ними; після 5 — 7 днів; після 7 — пауза.
- Якщо немає завершеного заняття 14 днів — не частіше разу на тиждень; 30 днів — пауза навіть без 7 повідомлень.
- Завершення заняття скидає лічильник ігнорування. Явний вибір часу також поновлює цикл. Сам клік без заняття не вважається навчанням.
- 30 підказок ідуть за кількістю успішних надсилань, потім цикл повторюється. Це не нескінченний генератор. Редагувати банк: bot/retention.py → TIPS.
- Час надсилання має 90-хвилинне вікно наздоганяння, але нічого не надсилається поза 09:00–22:00. Пропущені дні не надсилаються пачкою.
- У кожному повідомленні — заняття, час, вимкнення. На першому — пояснення автоматичного режиму.
- TelegramForbiddenError деактивує користувача. Звичайний timeout не позначає його заблокованим. При 429 розсилка зупиняється щонайменше на retry_after.

Нагадування працюють у процесі бота. Якщо хостинг приспав або зупинив процес на все вікно надсилання, повідомлення буде пропущено. Для стабільного графіка потрібен процес, який працює у потрібний час; наявність коду не гарантує безперервної роботи хостингу.

## Як зупинити й відкотити

`RETENTION_ENABLED=false` у Render і перезапуск — вимикає планову розсилку всім, не змінюючи їхніх налаштувань. Типове значення — true. Якщо відкочуєшся на старий код, **спершу зупини процес і вимкни reminder_enabled в БД**, бо старий код не читає новий перемикач. Перш ніж це робити, збережи поточні налаштування користувачів для відновлення. Не видаляй таблицю доставок: вона потрібна для захисту від повторів та звіту.

Telegram не має ключа ідемпотентності для sendMessage. Якщо повідомлення надіслано, але запис результату не зберігся, його стан залишиться невідомим; того дня повтору не буде. При помилці одного пакета решта його зарезервованих повідомлень може бути пропущена. Тут обрано захист від дублювання; невідомі результати видно в звіті.
